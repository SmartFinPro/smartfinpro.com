## Raw-HTML / no-JS proof (spec invariant 12, operator merge blocker)

`e2e/research-raw-html.spec.ts` fetches each of the four hub routes with
`request.get()` (no browser scripting at all) and checks the response
against `e2e/fixtures/research-review-hrefs.json` — a fixture generated by
`npx tsx scripts/research/export-review-hrefs.mts`, which re-derives
`lib/research/catalog.ts`'s own `loadMarketReviewItems()` inclusion rule
(`slug !== 'index'`, numeric `rating`) directly from the MDX files on disk
via `getContentByMarketAndCategory()`/`marketCategories` — **never** by
importing `catalog.ts` itself (which is `import 'server-only'`-guarded and
cannot run in a plain script) and **never** by reading the expected list
back off the page under test.

Fixture counts: `us: 68`, `uk: 40`, `ca: 33`, `au: 35` rated review hrefs.

Test 1 (`raw HTML contains every review href, with real titles behind the
first/middle/last links`) does two things per market, per the operator's
"prove content, not a container" requirement:

1. Asserts **every** fixtured href appears as `href="..."` in the raw HTML
   (100% coverage, invariant 12) — not a sample.
2. For the **first**, a **middle**, and the **last** href specifically,
   extracts the real anchor text immediately behind that href (via
   `firstAnchorText()`, matching the FIRST `<a href="...">text</a>` in
   document order — both card components put the title `<Link>` before any
   CTA button reusing the same href) and asserts it is non-empty,
   human-readable text (length > 2), not merely that a wrapper/`<article>`
   element exists.

## Analytics — surface/topic on the wire + invariant 13 (`research-tracking.spec.ts`)

Both GLOBAL events now explicitly assert `surface`/`topic` on the wire (they
were previously covered only indirectly):

- `a settled search sends the query LENGTH and the result count — never the
  query` — added `expect(props(events[0]).surface).toBe('hub')` and
  `expect(props(events[0]).topic).toBe('hub')`.
- `a filter chip sends the facet, its value and the resulting count` — same
  two assertions added.

The existing `a known dossier entry (eToro, provisional) reports its exact
identity fields on review click` test already asserted
`category === 'trading'` / `topic === 'trading-platforms'` for an ITEM
event (pre-Task-8) — confirmed still green, cited here rather than
duplicated.

**New invariant-13 test** (`invariant 13: hero, category totals, and a
tracked filter all agree with what is actually rendered`): the shipped PR 2
UI does not paint a literal number on each Category chip
(`FilterChips.tsx` renders `option.label` only — `count` is computed by
`computeDiscoveryFacets` but never painted) and has no distinct "view all"
control of its own (that CTA's `trigger: 'view_all'` property is reserved
in `lib/analytics/research-events.ts` for the Quick Finder, which ships in
PR 3). The test therefore proves the invariant through the count-bearing
surfaces that exist today:

1. The hero's default "Products" tile count == the independently-rendered
   total article count on the unfiltered page.
2. The sum of every Category chip's own independently-rendered count (click
   each chip in turn, count, Reset, repeat) == that same unfiltered total —
   mathematically guaranteed since every product has exactly one category.
3. One tracked `research_filter_change.resultCount` (status=provisional) ==
   the independently-rendered count for that filtered state.

All three held; PASS in 4.8s (given `test.setTimeout(45_000)` for the
6-category click/reset loop on the US catalog).
